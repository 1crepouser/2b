# Решения и допущения

Там, где ТЗ не даёт однозначного ответа, решения такие:

1. **Удаление задачи не удаляет её историю.** Иначе удаление стало бы способом стереть журнал. После удаления запись видит только постановщик.
2. **Объект с задачами удалить нельзя.** Сначала нужно удалить или перенести задачи, чтобы они не исчезали незаметно.
3. **Исполнитель видит имена и роли всех сотрудников.** Имена нужны в истории. Если это лишнее, профили можно закрыть и отдавать имена через отдельную функцию.
4. **Постановщик не может быть исполнителем.** Назначить можно только пользователя с ролью исполнителя.
5. **Постановщик может редактировать и переназначать задачу в любом статусе.** В ТЗ нет ограничения. Правки полей и смена исполнителя в истории не записываются, потому что история по ТЗ хранит смену статусов.
6. **При переназначении историю задачи видит новый исполнитель**, а прежний теряет к ней доступ.
7. **Комментарий необязателен всюду, кроме возврата на доработку.** Строка из одних пробелов считается пустой.
8. **Из статуса «Принята» переходов нет.** Переоткрыть принятую задачу нельзя.
9. **Правки объектов и задач не журналируются,** кроме смены статусов.

## Что не успел

- Нет постраничной загрузки и поиска: для тестового объёма данных они не нужны.
- Нет автоматических тестов интерфейса. Правила проверены тестами через API.
- Обновление данных между пользователями только при перезагрузке страницы, без realtime.
