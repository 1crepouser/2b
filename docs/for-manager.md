# Объяснение для руководителя

**Как устроена система.** Постановщик заводит стройки и задачи по ним, а затем назначает исполнителя. Исполнитель берёт задачу в работу и отдаёт на проверку. Постановщик принимает её или возвращает на доработку с комментарием. Каждая смена статуса попадает в историю: кто, когда и что изменил.

**Как защищены данные.** Правила проверяет сама база данных, а не только экран приложения. Поэтому даже человек, который умеет отправлять запросы в обход сайта, получит тот же отказ. Войти можно только с аккаунтом, который создал администратор: самостоятельной регистрации нет. Служебный ключ с полным доступом хранится отдельно и не попадает ни на сайт, ни в код.

**Что не может исполнитель:**
- видеть чужие задачи и стройки, где у него нет задач;
- создавать, менять и удалять задачи и стройки;
- принять свою задачу или перепрыгнуть через этап проверки;
- брать в работу чужую задачу;
- изменить или удалить запись в истории.

Постановщик тоже не может подделать историю или поставить задаче произвольный статус: статусы идут только по утверждённой схеме.
